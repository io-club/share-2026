## IDE、编译器与工具链

在正式开始之前，我想先纠正一个新生经常存在的误区，那就是需要区分 IDE 和编译器。

IDE 是集成开发环境（Integrated Development Environment）。Visual Studio 就是典型的 IDE，而 VS Code 本身主要是一个代码编辑器。

从最基本的功能来看，代码编辑器和记事本一样，都能够编辑文本，只不过前者提供了大量面向编程的功能。IDE 则在编辑器的基础上，集成了编译、调试等开发工具。

编译器本身是一种软件。不太严谨地说，它负责将我们编写的源代码翻译成另一种形式的代码，例如机器代码。

所以，VS Code 本身是一个代码编辑器，经过各种配置，也可以承担类似 IDE 的功能。Clang 和 GCC 是编译器。使用 Windows 的同学可能下载过一个叫 MinGW 的东西，可以将它理解为一套工具链，其中就包含 GCC 编译器。

所谓工具链，就是与程序开发相关的一系列工具软件。大家在以后的学习中自然会逐渐接触这些概念。

## 什么是计算：从图灵机到 Lambda 演算

接下来进入正题。这一部分涉及一些计算机导论的知识。

很多人在进入大学之前没有接触过编程。不知道大家之前有没有思考过，计算机究竟是如何进行计算的？或者说，抛开计算机，数学上究竟应该如何定义“计算”？

究竟什么样的问题，可以通过一套明确、机械化的规则求解？这个问题后来发展成了可计算性理论。

这就引出了计算机科学历史上两位非常重要的数学家：Alan Turing 和 Alonzo Church。

前者提出了图灵机，后者提出了 Lambda 演算。图灵机是我们 CS 学生经常接触的基础概念，而 Lambda 演算则是一套严格的形式化计算体系。由于时间有限，这里就不具体展开了。

我可以稍微拓展一下。实际上，关于可计算性，还有其他的形式化表达方式，比如 μ-递归函数等。

在很多 CS 学生的世界观里，图灵机似乎什么都能干，但事实上，计算存在理论上的边界。

例如，数学上绝大多数实数都是不可计算的。也就是说，不存在一个算法，能够按照任意给定的精度要求，计算出这些实数的近似值。

除此之外，数学中的某些形式公理系统，在可证明性方面也存在理论上的局限。不过，这些主要是数学家研究的问题，我们今天就不展开了。

## 类型论、范畴论与编程范式

好在无类型 Lambda 演算和图灵机在计算能力上是等价的。这里提到的“类型”，与编程语言中的类型概念存在一定联系。

很久以前，罗素提出了著名的罗素悖论，也就是考虑“所有不包含自身的集合所构成的集合”，这一问题直接冲击了当时数学的基础。

类型论也是在这样的数学基础研究背景下发展起来的。除此之外，还有范畴论。这两个理论领域在 PL 研究中都具有重要地位，不过我自己还没有系统学习过，所以就不多展开了。

Lambda 演算和图灵机所体现的不同计算思想，也能够帮助我们理解编程语言中的不同编程范式。

从一个比较粗略的角度来看，可以将编程范式分为命令式和声明式两大类。

命令式编程是大家非常熟悉的形式，例如使用 Python、C、C++ 编写程序时常见的方式。它通常需要我们一步一步地描述计算过程，通过赋值、循环等操作改变程序状态，最终得到计算结果。

而声明式编程更强调描述我们希望得到什么结果，而不是具体应该如何一步一步执行。

以声明式编程中的函数式编程为例，它更加接近数学表达式，通过定义函数、函数组合和表达式求值获得结果。

- 第二个是函数式风格的实现。实际上，我们可以将其中的排序逻辑表示为递归函数，甚至将其翻译成对应的数学表达式。

我这里只是展示两种不同的编程风格，不需要大家关心具体的排序算法。

在具备足够表达能力的情况下，这两种编程范式可以具有等价的计算能力。这也是一件非常有意思的事情。感兴趣的同学可以尝试学习一下函数式编程。

## 为什么要学习编译原理

接下来进入编译器部分。

客观来讲，对于普通的 CS 学生而言，掌握编译器的基本使用方法就足够了。甚至很多人可能直到毕业，也没有亲自敲过几条编译指令。

而且，编译原理也不属于 408 的考核范围。

但是，如果你想成为一名有味道的 CS 学生，那么我非常推荐学习操作系统、编译原理、计算机网络、计算机组成原理、算法与数据结构等课程。

总之，我非常推荐真正喜欢 CS 的学生去学习这些基础知识。

好，下面，我们可以简单看一下这段check函数，判断 x + 1 > x，至少在数学上的有序域上这个表达式永远成立，但是学习过c语言的我们应该都知道，这个x其实是可能溢出的，他理论上是可能返回false的，但是事实怎么样呢？编译器认为他永远为真，这就是ub，undefined behavior，这里就讲个例子，这里就不展开ub了。

再来看一下这个三个函数，他们有的在循环里重复计算了(x + y)，而且还写了两遍，有的用变量存储了中间结果，有的把中间结果放到了循环之外。所以说，我们要不要担心他的性能问题呢？这里看似执行了多次不必要的运算，而且有的似乎执行了多此t变量赋值，但实际上他们在gcc编译器开启o2后生成的代码是一样的。

这也就是为什么，我推荐CS学生学习编译原理，编译原理给你带来的收益可能没有机器学习，Web前后端那么直接，他带来的是一种非常内敛专业的收益。

这里列出的就是为什么要学习编译原理呀，最直接也是最功利的一点就是CS专业的学生本科期间是有这门课的。

然后，如果某一天你可能处于某些原因学习了汇编语言，你觉得用高级语言编程都弱爆了，你要写汇编，然后就惊讶的发现，同样的算法，你写的居然会比编译器生成的慢这么多，或者呢有些同学尤其是学习嵌入式的同学，会经常看到一个奇怪的关键字volatile，不写还会出现奇奇怪怪的错误。又或者你真的学习了函数式你发现哇塞，他们怎么写代码都不考虑性能呀。又又又或者，你就职了某个公司，公司业务代码写的乱七八糟，老板让你写一个程序检查会不会死循环，程序能不能正常执行，你非常笃定的告诉他这是图灵机停机问题，然后他依然让你想办法克服一下。

以及我觉得最重要的一点就是你能对你写的代码有一个大体的把握，也能知道什么样的代码不用担心，什么样的代码是看似正确的。

接下来我们可以介绍一下，我们PL领域有哪些事情可以做，这里列的都是大方向，有的是做学术，有的是工作方向，比如编译器优化，这里就是我说为什么手搓汇编可能比不过编译器。编译器可以通过通过程序分析和各种优化算法，去优化，得到效率更高的代码。当然，也有一些研究会利用形式化方法证明这些优化的正确性。

第二类就是PA，也就是程序分析，他主要研究程序可能发生什么、研究怎么证明程序满足给定的形式化规范，因此他可以扫描或者追踪一些潜在的错误。尤其是近期的rust，他有各种checker，这是一个程序分析非常好的一个例子，这里插一句，非常推荐大家学习CPP然后学习Rust，rust是一个非常现代的语言，现代理念和现代工具，用起来非常舒服。

第三类是编程语言，这个方向有点小众，因为他直接研究编程语言本身，可能是编程范式，可能是前端之类的东西，这个方向我不太懂。

第四类就是测试与编译器验证，代码测试软件工程的一个重要阶段，编译器自然也需要测试，而且编译器如果出过后果更加的可怕，因此编译器的测试非常重要，这里包括单元测试和集成测试，比如可以利用形式化方法生成随机代码做差分测试、模糊测试，另一类工作是编译器验证，尝试利用形式化方法证明编译器或某些编译转换的正确性。

第五类是AI带起来的方向，AI的大模型训练和部署要依赖于显卡芯片设计，也要依赖分布式计算，还要设计好AI模型怎么得到GPU可执行的代码，部分算子之间能不能优化，AI厂商需要有人做算子优化，代码生成。属于AI infrastructure中贴近硬件层的部分。

## 普通 CS 学生应该如何学习编译器？

最后简单收个尾吧，对于CS专业的学生，编译原理是必修课，所以你是必须要学的，不过好在很多内容都是编译器前端内容，也就是学习怎么解析编程语言，有一些简单的中端优化内容，后端代码生成几乎没有。

对于感兴趣的同学，可以自己读读书，尝试写写代码

可以学着用工具，比如 flex，yacc/Bison，做个前端小demo，还有的话，后面可以自己尝试试一试能不能写一个简单flex bison出来，或者实现一个简单的编程语言，而且我建议尝试其他设计用来练手语言，或者C的子集，不要尝试实现标准C语言。

最重要的是读书，理解现代优化方法，可以了解一下 LLVM
